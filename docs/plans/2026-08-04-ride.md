# RIDE (PDF + QR) — Plan de Implementación

**Goal:** Añadir la Representación Impresa de Documento Electrónico (RIDE) en PDF
con código QR para los 6 comprobantes, como submódulo opcional `sri-ec/ride`.

**Architecture:** Motor de layout compartido (bloques comunes del RIDE: cabecera
del emisor, datos del comprobante con QR, datos del comprador, pie de información
adicional) + un renderizador de cuerpo por tipo de documento. `pdfkit` y `qrcode`
como `optionalDependencies`, cargadas de forma perezosa: quien no use el RIDE no
las instala ni las carga.

**Tech Stack:** pdfkit, qrcode, TypeScript strict, vitest, tsup (nueva entrada de
build para el subpath).

## Global Constraints

- El core (`sri-ec`) NO debe importar nada del RIDE. El subpath `sri-ec/ride` es
  la única puerta de entrada; el árbol de dependencias de quien solo emite no
  cambia.
- `pdfkit` y `qrcode` van en `optionalDependencies` + `peerDependenciesMeta`
  opcional. Si faltan al llamar al RIDE, lanzar un error claro que diga
  exactamente qué instalar.
- Node ≥ 20, TypeScript strict, sin binarios nativos.
- La API devuelve `Promise<Uint8Array>` (bytes del PDF). Nada de escribir a disco
  desde la librería.
- Todo en español en la salida impresa (es un documento fiscal ecuatoriano).
- Los montos se formatean con `formatMonto` del core; nunca aritmética flotante.
- Commits convencionales terminados en:

  `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`

## API pública del submódulo

```ts
import { generarRide } from 'sri-ec/ride';

const pdf: Uint8Array = await generarRide({
  documento,                    // Comprobante (union de los 6)
  claveAcceso,                  // string 49 dígitos
  autorizacion: {               // opcional: si falta, el RIDE sale sin autorizar
    numero: string,
    fecha: string,
  },
  logo?: Uint8Array,            // PNG/JPG opcional del emisor
  opciones?: {
    tamano?: 'A4' | 'LETTER',   // default 'A4'
    incluirQr?: boolean,        // default true
  },
});
```

Además un atajo por tipo si resulta natural (`generarRideFactura`, etc.), pero
`generarRide` despacha por `documento.tipo` y es la API principal.

El QR codifica la clave de acceso (49 dígitos), que es lo que permite verificar
el comprobante en el portal del SRI.

## Bloques obligatorios del RIDE

Estos campos son los que exige el SRI; el renderizador debe emitirlos todos
cuando existan en el documento.

**Cabecera — emisor (columna izquierda):** logo si se pasa, razón social, nombre
comercial si existe, dirección matriz, dirección del establecimiento, "OBLIGADO A
LLEVAR CONTABILIDAD: SI/NO", contribuyente especial si aplica, agente de
retención si aplica, contribuyente RIMPE si aplica.

**Cabecera — comprobante (columna derecha):** R.U.C., nombre del documento
("FACTURA", "NOTA DE CRÉDITO", …), número `estab-ptoEmi-secuencial`, número de
autorización, fecha y hora de autorización, ambiente (PRUEBAS/PRODUCCIÓN),
emisión (NORMAL), clave de acceso y su QR.

**Bloque comprador:** razón social o nombres, identificación, fecha de emisión,
dirección si existe, guía de remisión si existe.

**Detalle:** tabla con código principal, código auxiliar, cantidad, descripción,
detalles adicionales, precio unitario, descuento, precio total.

**Totales:** subtotales por tarifa (15%, 0%, no objeto de IVA, exento),
subtotal sin impuestos, total descuento, ICE, IVA, propina, valor total.

**Formas de pago:** forma de pago, valor, plazo, unidad de tiempo.

**Información adicional:** los `campoAdicional` del documento.

**Extras por tipo:** nota de crédito → comprobante que modifica, motivo, valor de
modificación. Nota de débito → motivos. Retención → periodo fiscal y tabla de
documentos sustento con base, porcentaje y valor retenido. Guía de remisión →
transportista, placa, fechas de transporte, destinatarios con sus detalles.
Liquidación de compra → datos del proveedor.
